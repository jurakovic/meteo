# Refactoring plan

Architecture review of the site's code (mainly `src/_assets/js`) and the work that follows from it. Each step is verified (lint, tests, a browser pass, a full build), committed and pushed on its own. The status column is kept up to date as the work goes.

Status: ⬜ todo · 🔄 in progress · ✅ done

## Log

- **S0** — `build.ps1` made path-agnostic (component filter, relative path, output path, `New-Item` instead of `mkdir -Force`). On Linux with PowerShell 7 the build of the unchanged source reproduces the committed `docs/` and minified files exactly.
- **S1** — `npm run test:e2e`: 58 Playwright tests (×2: the dev tree and the built site) over the landing page, the settings dialog, pop-out widgets, the dashboard, auto-refresh and a phone. `tests/serve.mjs` serves `src/` and `docs/` (under `/meteo/`), and `tests/e2e/fixtures.js` answers every outside request (images, frames, the worker's `config.json`), so the suite runs offline and fails on any script error. B1 is marked as an expected failure until it is fixed. Stable over three repeats.
- **S2** — Removed `GetLastInit`/`DTGFromDateInHours`/`EndValue`/`pad`, the `resetIframePosition` wrapper, the commented-out catalog entries (Meteociel's sandwich slides and Időkép's Adria radar — still in git history, e.g. `6f35625:src/_assets/js/maps.js`) and with them `videoClass` and `.vid2`. `withPersistPaused(fn)` replaces the five set/reset pairs of `snapPersistPaused` and restores the previous value in a `finally`; `applySnapLayout`'s placing part became `placeSnapLayout`. `storeShownList` replaces the twin bodies of `removeMapFromList`/`addMapToList`, `appendMapRows` the row building repeated in `renderMaps` and `addToDashboard`, and `catalogMap(id)` (a `Map` index) the nine `MAP_CATALOG.find` scans. The meteogram page builds its frame with DOM calls instead of `document.write`. **B1** fixed: the arrangement kept at the breakpoint is the stored one, not one read off the already-narrowed screen. **B2** fixed. The helpers duplicated *across* files wait for S4: without modules, sharing them would need yet another global script and load-order care — which the first attempt here ran into (`maps.js` renders before `main.js` is loaded in dev).
- **S3** — `npm run build` (`scripts/build.mjs`, `scripts/manual.mjs`) replaces `build.ps1`, `md.ps1`, `unix2dos` and the hand-run terser/clean-css step: it minifies in memory, so the committed `.min.*` files are gone, and it writes CRLF itself. Checked against the PowerShell build on the same source: `docs/` and the manual fragment byte for byte identical. `src/build.sh` is kept as a wrapper. `npm run lint` (ESLint, recommended rules; `no-undef`/`no-unused-vars` off for the site's scripts until they are modules), `npm test` (`node --test`, 6 tests for the manual converter), `npm run check` for everything. `INTERNALS.md` *Commands*/*Build*/*Tests* and the manual's build notes rewritten to match.
- **S4** — The four scripts became 40 ES modules (`lib/`, `page/`, `maps/`, `settings/`, `widgets/`, plus `remote-config.js`), each declaring only; two entries (`landing.js`, `customize.js`) wire them in the order the built page ran them, with `onReady` giving every start-up step its own error boundary. The split was done by a script that moved every top-level declaration verbatim and computed the imports and exports, so no function body was retyped; the 20 load-time statements became `init…` functions. Merged on the way: `clamp`/`dialogClamp`, `roundFraction`/`dialogFraction`, the two viewport pairs, the two pointer trackers (`lib/pointer.js`, `trackWidgetPointer` adds the shadows), the two media queries (`DESKTOP_MQ`), the two handle lists, `mapSettingsOpen`/`anyDialogOpen`, the five copies of the text-field guard (`isTextField`), and the 800 px checks (`isNarrowViewport`). The dialog no longer calls into the columns (`typeof layoutSnapColumns`): the customize entry relays `dialog-toggled` to them. Inline `onclick`/`onchange` replaced by `data-action` and one delegated listener (`page/actions.js`), which the rendered slideshow arrows and frame buttons use too. Cross-module writes replaced by owners' functions (`newGroupId`, `updateIframeSrc(force)`, `setScrollbarGutter`). ESLint now runs with `no-undef` and `no-unused-vars` on. The build bundles each entry with esbuild and minifies with terser (esbuild's own line limit breaks lines inside strings, which the indentation then corrupts — caught by the built-site tests); the built pages shrank (landing 126.5 → 123.2 KB, customize 199.5 → 179.0 KB). `INTERNALS.md` gained a code map.
- **S5** — `buildMapSettings` (867 lines) became a Mediator: `settings/panel.js` builds the panel object — what the dialog is editing (`editingPresetId`, the board and grid ticks) and the few operations that cross sections (`listEdited`, `presetChosen`, `presetsChanged`, `setDashboardChecked`, `close`) — and the sections, which no longer call one another: `panel-presets.js` (the bar), `panel-list.js` (the two lists, sort, find, drag), `panel-rows.js` (mode, refresh, layout line), `panel-manage.js` (saved and built-in presets); what the dialog would apply or share is worked out without a DOM in `panel-view.js`. `sanitizeSnapLayout` split into `sanitizeColumn`/`sanitizeFloating`/`sanitizeEntryTail`/`dropLoneGroups` (key order kept: layouts are compared as JSON, and stored ones must still compare equal); `resizePopout` into `resizePane`/`resizeFloating`/`lockedResizeWidth`; the slideshow's swipe into touch, mouse and pinch-guard binders; the widget gestures into named handlers; `pulledSize` (lib/pointer.js) replaces three copies of the handle arithmetic. The K and Enter keys now use `isTextField` too (S4 had missed them). 30 unit tests (`npm test`) cover the catalog and presets, find, preferences, share links, instance keys, tiling, magnets, groups, the fullscreen's free room, `sanitizeSnapLayout` and the dialog's view functions, with `window`/`localStorage` stubbed (tests/unit/setup.mjs).
- **S6** — `lib/storage.js`: every key the site stores listed in one place (`STORAGE_KEYS`, with what reads it), and `readJson`/`writeJson`/`removeKey`, which never throw; the nine hand-written try/catch pairs across seven modules are gone, each module keeping only its own validation of what it reads. A write storage refuses is kept in memory and read back for the rest of the session, which fixes **B3**; `page/links.js`, which called `localStorage` unguarded, now goes through it too (its `"1"`/`"0"` values are JSON already, so nothing stored changes). `features.js` holds the switches for parts built but not offered yet (the manual). Tests: 3 unit tests for the storage helpers, and a browser test with storage refused on both pages.
- **S7** — Rather than one central store (more indirection than this page needs), every piece of state now has exactly one owning module and is read through its functions: `dashboardMode`, `userPresets`, `hiddenPresets`, `sharedMapView` and `snapColumns` are no longer exported variables other modules read (or, for the columns, wrote); `isDashboard()`, `getUserPresets()`, `getHiddenPresets()`, `getSharedMapView()`, `snapColumn(side)`/`setSnapColumnWidth` stand in. `lib/events.js` names every event the page uses and gives `emit`/`on`; the three existing CustomEvents go through it, and the grid, refresh and layout modules announce `grid-changed`, `refresh-changed`, `refresh-tick`, `layout-changed` instead of calling into the tab (`syncMsTab`, `syncRefreshLabels`, `applyStoredMsTab`) and the dialog (`panel._onGridChange`, `_onRefreshChange`, `_onLayoutChange`, which hung off the DOM element). The dialog subscribes once and hands events to the instance that is open. `persistSnapLayout` is `arrangementChanged` — named for what it is and documenting its three consequences — and the writing itself moved to the module that owns the view (`storeViewLayout`, maps/prefs.js); `updateCovered` is `refreshOverlap`, the covered frames (`markCovered`), the fullscreen's room and the shadows as three explicit steps. Two browser tests added (G with the dialog open, the dialog's countdown ticking).
- **S8** — `page/commands.js` (which replaces `page/actions.js`) registers every action a control or a key can run by id: what runs it, the keys bound to it and when a key may (`keyWhen`). One click listener runs the `data-action` controls — the markup's, the rendered frame buttons, the tab's glyphs, the dialog's Posloži — and one captured keydown listener runs the keys, the first bound command whose `keyWhen` holds taking the key; the text-field and modifier guard is written once there (`widgets/keyboard.js` still had its own copy). The five keydown listeners in four modules are gone: Escape (dialog, then fullscreen — now exclusive by `keyWhen` instead of by registration order), K, Enter, H, R, G, S, A, D and the arrows are commands of the modules that own them. Titles are built from the registry (`withKey('Osvježi sve karte', 'reload')` → "Osvježi sve karte (R)"), so a rebound key cannot leave a stale title. **B4** fixed: Escape leaving a fullscreen map is a page command, on both pages. ESLint now also checks imports against exports (`eslint-plugin-import-x`), which esbuild had had to catch at build time.
