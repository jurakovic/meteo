# Refactoring plan

Architecture review of the site's code (mainly `src/_assets/js`) and the work that follows from it. Each step is verified (lint, tests, a browser pass, a full build), committed and pushed on its own. The status column is kept up to date as the work goes.

Status: ⬜ todo · 🔄 in progress · ✅ done

## Log

- **S0** — `build.ps1` made path-agnostic (component filter, relative path, output path, `New-Item` instead of `mkdir -Force`). On Linux with PowerShell 7 the build of the unchanged source reproduces the committed `docs/` and minified files exactly.
- **S1** — `npm run test:e2e`: 58 Playwright tests (×2: the dev tree and the built site) over the landing page, the settings dialog, pop-out widgets, the dashboard, auto-refresh and a phone. `tests/serve.mjs` serves `src/` and `docs/` (under `/meteo/`), and `tests/e2e/fixtures.js` answers every outside request (images, frames, the worker's `config.json`), so the suite runs offline and fails on any script error. B1 is marked as an expected failure until it is fixed. Stable over three repeats.
- **S2** — Removed `GetLastInit`/`DTGFromDateInHours`/`EndValue`/`pad`, the `resetIframePosition` wrapper, the commented-out catalog entries (Meteociel's sandwich slides and Időkép's Adria radar — still in git history, e.g. `6f35625:src/_assets/js/maps.js`) and with them `videoClass` and `.vid2`. `withPersistPaused(fn)` replaces the five set/reset pairs of `snapPersistPaused` and restores the previous value in a `finally`; `applySnapLayout`'s placing part became `placeSnapLayout`. `storeShownList` replaces the twin bodies of `removeMapFromList`/`addMapToList`, `appendMapRows` the row building repeated in `renderMaps` and `addToDashboard`, and `catalogMap(id)` (a `Map` index) the nine `MAP_CATALOG.find` scans. The meteogram page builds its frame with DOM calls instead of `document.write`. **B1** fixed: the arrangement kept at the breakpoint is the stored one, not one read off the already-narrowed screen. **B2** fixed. The helpers duplicated *across* files wait for S4: without modules, sharing them would need yet another global script and load-order care — which the first attempt here ran into (`maps.js` renders before `main.js` is loaded in dev).
- **S3** — `npm run build` (`scripts/build.mjs`, `scripts/manual.mjs`) replaces `build.ps1`, `md.ps1`, `unix2dos` and the hand-run terser/clean-css step: it minifies in memory, so the committed `.min.*` files are gone, and it writes CRLF itself. Checked against the PowerShell build on the same source: `docs/` and the manual fragment byte for byte identical. `src/build.sh` is kept as a wrapper. `npm run lint` (ESLint, recommended rules; `no-undef`/`no-unused-vars` off for the site's scripts until they are modules), `npm test` (`node --test`, 6 tests for the manual converter), `npm run check` for everything. `INTERNALS.md` *Commands*/*Build*/*Tests* and the manual's build notes rewritten to match.
- **S4** — The four scripts became 40 ES modules (`lib/`, `page/`, `maps/`, `settings/`, `widgets/`, plus `remote-config.js`), each declaring only; two entries (`landing.js`, `customize.js`) wire them in the order the built page ran them, with `onReady` giving every start-up step its own error boundary. The split was done by a script that moved every top-level declaration verbatim and computed the imports and exports, so no function body was retyped; the 20 load-time statements became `init…` functions. Merged on the way: `clamp`/`dialogClamp`, `roundFraction`/`dialogFraction`, the two viewport pairs, the two pointer trackers (`lib/pointer.js`, `trackWidgetPointer` adds the shadows), the two media queries (`DESKTOP_MQ`), the two handle lists, `mapSettingsOpen`/`anyDialogOpen`, the five copies of the text-field guard (`isTextField`), and the 800 px checks (`isNarrowViewport`). The dialog no longer calls into the columns (`typeof layoutSnapColumns`): the customize entry relays `dialog-toggled` to them. Inline `onclick`/`onchange` replaced by `data-action` and one delegated listener (`page/actions.js`), which the rendered slideshow arrows and frame buttons use too. Cross-module writes replaced by owners' functions (`newGroupId`, `updateIframeSrc(force)`, `setScrollbarGutter`). ESLint now runs with `no-undef` and `no-unused-vars` on. The build bundles each entry with esbuild and minifies with terser (esbuild's own line limit breaks lines inside strings, which the indentation then corrupts — caught by the built-site tests); the built pages shrank (landing 126.5 → 123.2 KB, customize 199.5 → 179.0 KB). `INTERNALS.md` gained a code map.
- **S5** — `buildMapSettings` (867 lines) became a Mediator: `settings/panel.js` builds the panel object — what the dialog is editing (`editingPresetId`, the board and grid ticks) and the few operations that cross sections (`listEdited`, `presetChosen`, `presetsChanged`, `setDashboardChecked`, `close`) — and the sections, which no longer call one another: `panel-presets.js` (the bar), `panel-list.js` (the two lists, sort, find, drag), `panel-rows.js` (mode, refresh, layout line), `panel-manage.js` (saved and built-in presets); what the dialog would apply or share is worked out without a DOM in `panel-view.js`. `sanitizeSnapLayout` split into `sanitizeColumn`/`sanitizeFloating`/`sanitizeEntryTail`/`dropLoneGroups` (key order kept: layouts are compared as JSON, and stored ones must still compare equal); `resizePopout` into `resizePane`/`resizeFloating`/`lockedResizeWidth`; the slideshow's swipe into touch, mouse and pinch-guard binders; the widget gestures into named handlers; `pulledSize` (lib/pointer.js) replaces three copies of the handle arithmetic. The K and Enter keys now use `isTextField` too (S4 had missed them). 30 unit tests (`npm test`) cover the catalog and presets, find, preferences, share links, instance keys, tiling, magnets, groups, the fullscreen's free room, `sanitizeSnapLayout` and the dialog's view functions, with `window`/`localStorage` stubbed (tests/unit/setup.mjs).
- **S6** — `lib/storage.js`: every key the site stores listed in one place (`STORAGE_KEYS`, with what reads it), and `readJson`/`writeJson`/`removeKey`, which never throw; the nine hand-written try/catch pairs across seven modules are gone, each module keeping only its own validation of what it reads. A write storage refuses is kept in memory and read back for the rest of the session, which fixes **B3**; `page/links.js`, which called `localStorage` unguarded, now goes through it too (its `"1"`/`"0"` values are JSON already, so nothing stored changes). `features.js` holds the switches for parts built but not offered yet (the manual). Tests: 3 unit tests for the storage helpers, and a browser test with storage refused on both pages.
- **S7** — Rather than one central store (more indirection than this page needs), every piece of state now has exactly one owning module and is read through its functions: `dashboardMode`, `userPresets`, `hiddenPresets`, `sharedMapView` and `snapColumns` are no longer exported variables other modules read (or, for the columns, wrote); `isDashboard()`, `getUserPresets()`, `getHiddenPresets()`, `getSharedMapView()`, `snapColumn(side)`/`setSnapColumnWidth` stand in. `lib/events.js` names every event the page uses and gives `emit`/`on`; the three existing CustomEvents go through it, and the grid, refresh and layout modules announce `grid-changed`, `refresh-changed`, `refresh-tick`, `layout-changed` instead of calling into the tab (`syncMsTab`, `syncRefreshLabels`, `applyStoredMsTab`) and the dialog (`panel._onGridChange`, `_onRefreshChange`, `_onLayoutChange`, which hung off the DOM element). The dialog subscribes once and hands events to the instance that is open. `persistSnapLayout` is `arrangementChanged` — named for what it is and documenting its three consequences — and the writing itself moved to the module that owns the view (`storeViewLayout`, maps/prefs.js); `updateCovered` is `refreshOverlap`, the covered frames (`markCovered`), the fullscreen's room and the shadows as three explicit steps. Two browser tests added (G with the dialog open, the dialog's countdown ticking).
- **S8** — `page/commands.js` (which replaces `page/actions.js`) registers every action a control or a key can run by id: what runs it, the keys bound to it and when a key may (`keyWhen`). One click listener runs the `data-action` controls — the markup's, the rendered frame buttons, the tab's glyphs, the dialog's Posloži — and one captured keydown listener runs the keys, the first bound command whose `keyWhen` holds taking the key; the text-field and modifier guard is written once there (`widgets/keyboard.js` still had its own copy). The five keydown listeners in four modules are gone: Escape (dialog, then fullscreen — now exclusive by `keyWhen` instead of by registration order), K, Enter, H, R, G, S, A, D and the arrows are commands of the modules that own them. Titles are built from the registry (`withKey('Osvježi sve karte', 'reload')` → "Osvježi sve karte (R)"), so a rebound key cannot leave a stale title. **B4** fixed: Escape leaving a fullscreen map is a page command, on both pages. ESLint now also checks imports against exports (`eslint-plugin-import-x`), which esbuild had had to catch at build time.
- **S9** — `maps/types.js`: one entry per kind of map (`slideshow`, `image`, `video`, `iframe`, `iframe-basic`) with its build function, whether its widget is sized freely (`freeAspect`), whether it has a fullscreen of its own, and how it is fetched afresh (`reload`, null for the live interactive maps). `buildMapContent`'s switch, `isFreePopout`'s `.if1, .if2` probe, `hasFullscreen`'s `type === 'iframe'` and the reload selectors all ask the registry now, so a new kind of map is one entry and a build function. `mapAspect` (arrange) stays with the rendered content — it measures the image or video actually shown, whatever the type. Tests: every catalog map has a registered type; `freshUrl`; and a browser test that R re-fetches frames and images but not the interactive maps.
- **S10** — The interactive map's gate button is a state machine: `data-state` is `hidden`, `exit` ([X]), `reset` ([R]) or `fullscreen` ([R] that stays), set by one function (`setGateState`) and read by the others, instead of being inferred from the button's label (`textContent === '[R]'`) and swapped for a clone on every change to shed its listeners; a press runs the `gate` command through the one click listener. No DOM element carries state of the site's any more: a widget's group (`groupOf`/`setGroupOf`, widgets/groups.js), its gap and the gap's way back (`handGapTo`, widgets/popout.js), its shadow (`dropShadow`, widgets/overlap.js), the gate's state before a fullscreen and the hints' timers (page/iframe.js) live in `WeakMap`s of the module that owns them; the progress bar's run and the resize timers are module variables. Browser tests added for the gate's zoom and fullscreen transitions and for a copy taking over the original's place.
- **S11** — The landing page's ~650 hand-written lines of map rows are gone: `maps/landing.js` draws the default view from the catalog with the customize page's renderer, and `DEFAULT_MAPS` moved into the catalog as the one list both pages start from. Generating the rows at build time was weighed and dropped: the dev pages are served straight from `src/`, so the rows would have had to be written back into the source tree (which the old build deliberately never did) or fetched after the page's wiring had already run. Rendering at load needs neither, and the render is the one the customize page already runs. To keep the landing page's script free of the widgets, `maps/render.js` no longer imports them: a title bar's extra buttons come in as an option (`titleButtons`), which the customize page, the copies and the board pass (`WIDGET_RENDER`, widgets/popout.js) — the landing bundle holds no widget module (checked with esbuild's metafile). The customize page's render moved to `maps/view.js`. `styleDisabledMaps` (a `<style>` hiding the static rows of a switched-off map) is gone with the rows: both pages leave such a map out and draw again on a change. Checked before the switch, with the catalog rendered under Node (linkedom) against the static markup, attribute by attribute: the same images, links, frames, styles and lazy slides for all 16 maps, the one difference being the camera's title, whose fuller form the catalog now carries as `title`. The landing page is 723 → 88 lines of HTML, and the built page 124 → 116 KB. The one thing given up: with scripts off, the landing page shows no maps (the customize page never did). Tests: the landing page shows the 16 maps without widget buttons, and a switched-off map is left out rather than hidden.
- **S12** — The stylesheet names its colours (16 `--c-*` custom properties on `:root`, which replace 67 hex literals) and its stacking layers (`--z-progress` … `--z-menu`, 16 of them): every page-level `z-index` is now one of those, in one ordered list, and the JavaScript reads the ones it needs from there (`cssNumber()` in `lib/dom.js`) instead of repeating 5000 and 4500 (`POPOUT_FS_Z` is gone). **B5** fixed on the way: a raise gives the widget the next number, and once the numbers reach the top of the widgets' band they are dealt afresh from its bottom, the order kept (`repackPopouts()`), so no amount of use lifts a widget over the columns' edges or a fullscreen map. The two pages lose their layout table: `<main class="maps">` holds the buttons, `<div data-maps>` with one `.map-entry` per map (its block and its links bar) and the links list, spaced by margins instead of spacer rows; `align` attributes and inline styles are gone from the markup (`[data-action]` gets its pointer from the stylesheet). The legacy `align="center"` centred narrower blocks as well as text, which is now said outright, and only in the page's flow — inside a widget, a flex column, an auto margin would shrink the title bar to its text (the visual comparison caught this). `removeFromDashboard()` takes one entry away instead of three rows found by walking siblings. Checked pixel for pixel against the previous build: 11 screenshots (both pages at desktop and phone width, the dialog, widgets, the board, fullscreen, the links bars and the links list) with no pixel changed. Tests: the widgets' layer holds after many raises (B5); the board's [x] and [+] leave one entry per map; an empty list shows its line and draws again.
- **S13** (types) — The JavaScript is type-checked: `jsconfig.json` turns on `checkJs` for every module under `src/_assets/js` (one switch instead of a `// @ts-check` line per file) and `npm run typecheck` runs `tsc` without emitting anything; `npm run check` runs it after the linter. The data the modules pass around has named types, defined next to the code that owns it: `CatalogMap` and `TitledSlide` (maps/catalog.js), `MapPrefs` (maps/prefs.js), `Preset` (maps/presets.js), `SnapLayout` with its column and entry shapes (widgets/layout.js), `SnapColumn` and `Pane` (widgets/columns.js) and `RenderOptions` (maps/render.js). The data layer (`lib/`, `maps/`, the layout API) has JSDoc on every export, and across the widgets every export's well-known parameters are typed (a `block` is always the widget's element, an `inst` its instance key, a `map` a catalog entry). `el()` returns the element type of its tag. The 77 errors the checker found at first were all a lookup typed as a bare `Element`: `queryAll()` and `query()` in `lib/dom.js` return HTML elements and replace the `[...document.querySelectorAll()]` idiom, which also gives event handlers their real event types. None of them was a bug. Also on the way: the three copies of "the image a widget shows" became `shownImage()` (widgets/core.js); the links list's expander was rewritten in the file's own style, with the same behaviour; and an import out of order in widgets/columns.js was moved.
- **S13** (comments) — The 31 comment blocks of eight lines or more inside the code, and nine wordy shorter ones, say the same in fewer words (the `//` lines go from 1,642 to 1,458, with the JSDoc added in the same step); what they explained at length is in `INTERNALS.md`. The comments were not stale history: the few mentions of earlier versions are compatibility notes (old share links, old stored layouts) and stay. Three blocks were two comments fused together by earlier moves, one of them describing a function it no longer sat on: `layout.js` (the arrangement's description now sits on the `SnapLayout` type), `panel.js` and `panel-rows.js`; each half is back above its own code.
- **S13** (INTERNALS.md) — Rewritten for the module tree, keeping the mechanism and dropping the retelling: 110.9 → 78.8 KB, the longest line 13,251 → 1,225 characters. It now has sections by area (maps, presets and share links, remote config, dialogs, widgets with one subsection per mechanism, storage, the manual), with lists where a paragraph was listing things, and new sections for how the modules work together (state, events, commands, the map-type registry, the dialog's mediator), the named types and the stacking layers. Every identifier and file it names was checked against the code: the old text named 20 that no longer existed (`POPOUT_MQ`, `persistSnapLayout`, `updateCovered`, `escapeFullscreen`, `setMapSettingsVisible`, `trackPopoutPointer`, `videoClass`…) and four deleted files (`main.js`, `maps.js`, `popout.js`, `config.js`). Stale passages removed or corrected: the dev loading-order note on `initRefresh()` (modules have no such order), a paragraph saying the manual is empty in dev (the build writes the fragment dev loads), a locked widget's "measured ceiling" (the CSS lifts the caps in a widget), and the dialog's gutter hand-off between scripts.
- **S14** — A sweep of the whole codebase for what is left of each finding. Clean: no globals or inline handlers (F1), no expando properties or state read off labels (F3), no events outside the bus (F4), no storage or media queries outside their modules (F5), no deprecated markup (F12), consistent style (quotes, `const`/`let`, strict equality), no dead CSS classes, nothing stale in the README. The long factories (`createPresetManager`, `createMapList`) are component closures of small inner functions and were left as they are. Fixed: six functions exported but used only in their own module are private again, and the one preset write done outside `maps/presets.js` (a rename mutating the array `getUserPresets()` hands out) is now `renameUserPreset()` there, so `saveUserPresets()` is private too. **B6** fixed in `page/progress.js`, which counts each image once per run; the synthetic `load` for complete images stays, since widgets refit on their map's load. Tests: rename refusals (unit), the progress bar ending at 100% (e2e).
